# Straton platform review — November 2026

Scope: engine (`crates/straton-engine`), connectors (`crates/straton-connectors`),
core types, desktop app (`apps/desktop`, React 19 + TypeScript + Tauri 2), CI and
supply chain. This document records what was reviewed, what was fixed in this
change, and what is recommended next, informed by how the major data platforms
solve the same problems.

## 1. Overall assessment

Straton is in much better shape than a typical v0.1. Strong points already in place:

| Area | What is already right |
| --- | --- |
| AuthN | 256-bit random bearer tokens, SHA-256 hashed at rest, expiry/revocation, disabled users, constant-cost lookup by hash |
| AuthZ | Default-deny route gate in `api.rs::auth`, per-source/per-dataset grants, row filters + column masks enforced inside the SQL catalog (not in the UI) |
| SQL sandbox | DataFusion `SQLOptions` disallow DDL/DML/statements; `information_schema` off; memory pool cap; query timeout; only snapshot Parquet files are registered, with canonicalised path-escape checks |
| Secrets | Write-only connector secrets in the OS keychain; never returned or logged |
| Encryption | Parquet modular encryption (AES-GCM), per-dataset DEKs wrapped by a keychain KEK, rotation |
| Audit | Hash-chained, append-only audit log with verify endpoint/CLI |
| Transport | Non-loopback HTTP and pgwire binds refuse to start without TLS |
| Desktop | Strict CSP, narrow Tauri capabilities, token stored in OS keychain, export path must come from the Save dialog, PKCE OAuth |
| Supply chain | cargo-deny (advisories, licenses, sources), npm audit, SBOMs, Sigstore-signed releases |
| Types | `strict: true` TypeScript, no `any`/`@ts-ignore`, `deny_unknown_fields` on every Rust request body |

Baseline at review time: `npm audit` → 0 vulnerabilities; `tsc -b` clean; all 18 desktop
test suites pass. Rust advisories are checked by `cargo deny` in CI (the latest commit
already patched RUSTSEC-2026-0384 in tokio).

## 2. Security findings fixed in this change

| # | Severity | Finding | Fix |
| --- | --- | --- | --- |
| S1 | **High** — privilege escalation / credential exfiltration | A user holding only a *scoped* `admin` grant on one source could `PUT /v1/sources/{id}` with a new `kind`, `host`, `path`, `api_base`, … The engine would then (a) send that source's stored keychain secret to an attacker-chosen host, or (b) open any SQLite/CSV file on the server — including the engine's own `state.db` (users, grants, wrapped DEKs, audit) — and sync it into a table the user can query. | Scoped admins may rename/tune a source but cannot change its `kind` or any connection-target field (`path, host, port, database, username, api_base, instance_url, login_url, client_id`); only global admins can repoint. Regression test: `scoped_source_admins_cannot_repoint_sources_and_engine_files_are_off_limits`. |
| S2 | **Medium** — sensitive file read | Even global admins could point a `sqlite`/`csv` source at the engine data or backup directory, making state.db, key sidecars and backups queryable and exportable through the normal (audited-as-data) SQL path. | `reject_engine_paths` canonicalises the configured path (resolving `..` and symlinks of the existing prefix) and rejects anything inside `data_dir` or `backup.dir`. |
| S3 | **Medium** — denial of service | The pgwire accept loop used `listener.accept()?`: a single transient error (EMFILE from fd exhaustion, ECONNABORTED) ended the task and took the SQL endpoint down until restart. There was also no limit on concurrent (including unauthenticated) connections. | Accept errors are logged and retried after 100 ms; at most 256 concurrent pgwire clients, extra sockets are closed. |
| S4 | **Medium** — memory DoS | `POST /v1/explorer/export` accepted an unbounded `max_rows` and buffers the whole file in memory before sending (outside the DataFusion memory pool). Any `read` user could request billions of rows. | Hard cap of 1,000,000 rows; larger values are rejected with 400. |
| S5 | **Low/Medium** — OAuth flow integrity (desktop) | The Salesforce loopback callback aborted the sign-in on the first `/OauthRedirect` hit with a wrong `state`, so any local process or web page (`<img src="http://localhost:1717/OauthRedirect">`) could cancel or race the real sign-in. A client that connected and never sent data blocked the listener for the whole 5-minute window. | Requests without the flow's `state` get 400 and are ignored; the state is compared in constant time; each connection has a 5 s read timeout. Tests cover forged callbacks, provider errors and idle sockets. |
| S6 | **Low** — defense in depth | API responses (query results, exports, audit) had no cache/sniffing/framing headers. | Every response now carries `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`, `Cross-Origin-Resource-Policy: same-origin`. |

### 2a. Review of the November push (MySQL/MongoDB/SQL Server/Neon, column lineage, optimizer)

- **Extended S1 to the new connectors.** Besides addresses, the new config fields include
  transport-security switches (`sslmode`, `ssl_mode`, `tls`, `encrypt`,
  `trust_server_certificate`, `ca_cert_path`, `options`) and `advisor_may_write`. A scoped
  admin flipping `trust_server_certificate=true` or `sslmode=disable` could intercept the
  stored password; flipping `advisor_may_write` would grant the engine write access to a
  production database. All are now global-admin-only.
- Advisor/optimizer routes fall through to the default admin-only branch of the auth gate and
  audit refused POSTs — correct. Apply/rollback require a fresh approval token bound to the
  exact source configuration — good design (similar to Databricks' "review before apply").
- Column lineage reuses `filtered_map` and redacts expressions for non-admins — correct.
- `cargo audit` on the merged tree: the three ignored zstd advisories are reachable only via
  `arrow-ipc` (`cargo tree -i zstd` confirms), so the documented justification holds.
  `rsa` (RUSTSEC-2023-0071, Marvin) is present in `Cargo.lock` only through sqlx's MySQL driver,
  which is not compiled (`cargo tree -i rsa` is empty; MySQL uses `mysql_async`). `rand 0.7.3`
  (unsound warning RUSTSEC-2026-0097) arrives via `tiberius → winauth` for Windows NTLM;
  consider disabling the `winauth` feature on non-Windows builds.

### 2b. Second pass (visual review and reliability)

| # | Severity | Finding | Fix |
| --- | --- | --- | --- |
| S7 | **Critical** — data loss on Linux | Secrets and the KEK used the `keyring` crate's `linux-native` backend: the kernel keyutils keyring, which its own docs describe as in-memory and cleared on reboot (systemd also gives each service start a fresh session keyring). With encryption on by default, a reboot made the engine refuse to start and every encrypted snapshot unrecoverable; connector passwords vanished too. Reproduced here: a second engine start failed with "KEK missing". | Opt-in file store (`[secrets] dir` / `STRATON_SECRETS_DIR`): owner-only files, hex-named, atomically replaced. Systemd unit sets it. Startup warns when the kernel keyring would be used; Settings shows the active store. Verified: encrypted sync, restart in a new session, decrypted query matches the source. |
| S8 | High — availability | `keys::initialize` ran even with encryption disabled, creating a KEK; a later start without it failed. | With encryption off no KEK is created, and a missing KEK only denies reads of earlier encrypted snapshots. |
| S9 | Medium — UI reliability | `queryApi` treated any unclassified client method as a mutation, invalidating every engine query, including the one awaiting the call: an endless refetch. New reads (`explorerProfile`, `engineSettings`) hit it. | Explicit read, transient and mutation lists; a test fails if any client method is unclassified or double-classified. |

UI defects fixed after rendering every page against a seeded engine (measured, not eyeballed): the title jumped 19px on Overview; the tab bar sat on a different surface with a 4px seam (a visible band in dark mode); two tab implementations had 4px and 16px spacing; content started 4px, 20px or 36px below the top bar; the SQL editor was a solid black block (canvas cannot parse `light-dark()` tokens); `cn()` dropped text colours next to theme font-size tokens; the lineage legend sat under the canvas tools; Connections showed "Configured" for every source. Settings is now a real page (desktop preferences, connection, effective engine configuration).

### 2c. Third pass (after the open-source release)

Full re-review of the engine, connectors, desktop shell, CI and deployment files on the
relicensed `main`, plus `cargo audit`, `cargo deny` and `npm audit`.

| # | Severity | Finding | Fix |
| --- | --- | --- | --- |
| S10 | **Medium** — metadata disclosure | Quality checks of kind `custom_sql` were validated as an internal admin principal and the planner error was returned to the caller. Any signed-in user could submit `SELECT nope FROM app_db.users` and read back "Valid fields are app_db.users.id, app_db.users.name": the columns of tables they cannot read. | Validation plans as the caller, so an unreadable table and a missing one give the same answer. Regression test reproduces the leak on the old code. |
| S11 | **Medium** — audit gap | Chart preview, chart data and drill-down run arbitrary user SQL (up to 5,000 rows) but wrote no `sql.query` audit row, so reads through charts left no trace. | Same audit row as the SQL endpoint, with `"via":"chart"`; rejected statements are recorded as `sql.rejected`. |
| S12 | **Medium** — weak pseudonymisation | The `hash` mask was unsalted SHA-256, and `straton_sha256` was callable from SQL. Low-entropy values (phone numbers, national IDs, birth dates) were reversible by hashing guesses, offline or through the engine itself. | HMAC-SHA256 under a per-`state.db` key that never leaves the engine; the mask function is placed in the plan, never registered, so SQL cannot call it. |
| S13 | Medium — supply chain | Stale advisory ignores: zstd 0.13.4 / zstd-safe 7.4.0 fix RUSTSEC-2026-0391, -0398 and -0403 (plus eleven unsoundness advisories) without leaving the 0.13 line. GitHub Actions used mutable tags, and `actions/checkout` left the workflow token in `.git/config` where any build script of the `contents: write` release job could read it. | Lockfile updated and the ignore list emptied (`cargo deny` passes). Actions pinned to SHAs, `persist-credentials: false`, release tools pinned. |
| S14 | Low/Medium — local disclosure | Outside the systemd unit (which sets `UMask=0077`), `state.db`, logs and backups were created world-readable under the default umask. | The engine sets umask 077 itself and warns about shared data and backup directories. |
| S15 | Low — SSRF bypass | The SaaS HTTP client followed redirects, so a vetted host could bounce the engine to any address. IPv4 targets wrapped in NAT64 (`64:ff9b::/96`), 6to4 and IPv4-compatible IPv6 skipped the egress classification. | Redirects are refused; embedded IPv4 addresses are classified like IPv4. |
| S16 | Low — masking | `last4` revealed values of four characters or fewer in full. | Such values show `****`. |
| S19 | Low — row-count disclosure | Quality checks evaluate with their owner's access, but every reader of the target could read each run's `observed` value and failing-row count. A reader whose row filter hides rows could learn the full table's row count (and how many rows match a `range` or `not_null` test), which the map and models API deliberately hide. Found while adding drift checks. | Counts, observations and drift details are returned only to the owner, admins and readers whose own policy is unfiltered; others see pass/fail. |
| S17 | Low — robustness | Dataset and source names such as `CON` or `com1` are device names on Windows. | Rejected as path components on Windows. |
| S18 | Info — hardening | The systemd unit scored 8.7 ("exposed") in `systemd-analyze security`; `rand 0.7` (unsound) reached Linux builds only through Windows NTLM support; the desktop declared an unused npm package. | Unit sandboxed (3.2, "OK"); NTLM support is Windows-only; package removed. |

Checked and found sound: the default-deny route gate and its contract test, token hashing and
revocation, the SQL sandbox (single read-only statement, no DDL/DML, no URL tables), view
models (invoker rights), quality checks and models evaluated as their owner, scoped-admin
repointing rules, pgwire startup parameter handling, path-component checks, snapshot
canonicalisation, the desktop CSP, Tauri capabilities and export path checks, and the CI
trigger model (`pull_request`, never `pull_request_target`). Remaining: `rsa` (Marvin) stays in
`Cargo.lock` only through sqlx's MySQL driver, which is not compiled; CSV exports do not
neutralise spreadsheet formulas (left as-is: exports must round-trip data exactly).

## 3. Security recommendations

1. ~~**SSRF egress policy for connectors.**~~ *Implemented (`egress.rs`): link-local and
   metadata addresses are always refused; `[network] allow_private = false` also refuses
   private ranges. Remaining gap: DNS rebinding between check and connect.* Original note: Global admins can still point Postgres/Stripe/Salesforce
   connectors at internal addresses (cloud metadata `169.254.169.254`, RFC1918). Add an
   `[network] allow_private = false` setting that resolves hostnames and refuses link-local,
   loopback and private ranges unless explicitly allowed — the pattern Snowflake (network rules /
   external access integrations) and Databricks (serverless egress control) use.
2. ~~**pgwire handshake timeout.**~~ *Implemented: clients must authenticate within 10 s.*
3. ~~**Login throttling / lockout telemetry.**~~ *Implemented as telemetry: per-address
   failure counts, an `auth.failures` audit row and admin notification at 20 failures in ten
   minutes, `GET /v1/admin/auth-failures`. No lockout, by design (shared proxy addresses).*
4. **SQLCipher for state.db** (already deferred in SECURITY.md) — closes the plaintext-metadata gap.
5. **mTLS between engine and remote desktop/SQL clients** (also deferred).
6. ~~**Runtime response validation in the desktop app.**~~ *Implemented without a new
   dependency (`lib/validate.ts`): `/v1/me`, `/v1/status`, `/v1/sql`, `/v1/sql/tables` and
   Explorer rows and profiles are checked; a mismatch names the field and the endpoint.*
7. ~~**IPv6 loopback.**~~ *Implemented: `http://[::1]` engines are accepted (the Tauri HTTP
   scope needs the escaped pattern `http://[\:\:1]:*`).*

## 4. UI / UX review (desktop)

virtualised result grid, explicit read-only scope component, automated contrast test across

### Open-source building blocks worth adopting

- **Apache Iceberg (`iceberg-rust`)** — table format, time travel, schema evolution; DataFusion integration.
- **delta-rs** — alternative if Delta compatibility (Databricks/Fabric) matters more than Iceberg.
- **Arrow Flight SQL (`arrow-flight`)** — high-throughput client protocol (ADBC drivers exist for Python/Go/Java).
- **Apache DataFusion Ballista / Comet** — distributed execution and Spark acceleration on the same engine.
- **Spark Connect** — let Spark clients submit work against Straton-managed tables.
- **OpenLineage** — emit lineage events in the standard format so Marquez/DataHub/Unity can consume them.
- **Unity Catalog OSS / Apache Polaris** — Iceberg REST catalog compatibility, so external engines can discover Straton tables.
- **MLflow** — experiment tracking and model registry.
- **Great Expectations / Soda Core** — reference vocabularies for quality checks.
- **Airbyte connector protocol / Meltano Singer taps** — reuse hundreds of community connectors via a subprocess adapter instead of writing every SaaS connector natively.
- **dbt Core / SQLMesh** — import existing transformation projects as Straton models.

## 6. New features added since this review

- `POST /v1/explorer/profile`: column profile over the policy-filtered table, honouring
  Explorer filters and search; numeric columns also get a twelve-bin histogram.
- **OpenLineage export** (`[lineage] openlineage_url`): run events for syncs and model runs,
  validated against the published schemas.
- **Tag-based masking**: tag columns once (`pii`), set one mask per role per tag.
- **Model expectations**: `warn`, `drop` and `fail` rules checked while a table model
  materializes, before publication.
- **Drift checks**: a quality check kind that profiles a table each run and compares it with
  the previous run.
- **Time travel**: `[snapshots] keep` and `schema."table@<time or run id>"`, with current
  policies applied to history.
- Desktop: tag management, expectations editor, snapshot picker, failed sign-ins tray, pipeline
  steps list, histogram profiles, drift check form.

## 7. Suggested roadmap

1. ~~Time travel~~ (done, on Straton's own snapshots). **Apache Iceberg** remains the largest
   strategic gap: it would let Spark, Trino and DuckDB read Straton tables. Kept snapshots map
   naturally onto Iceberg snapshots.
2. **Arrow Flight SQL** endpoint for bulk reads from Python, pandas and Polars.
3. ~~Connector egress policy~~ (done). **Postgres CDC** (logical replication, `pgoutput`)
   remains; it needs a replication slot lifecycle and a test Postgres in CI.
4. ~~Tag-based masking policies~~ (done).
5. ~~Quality checks as expectations; drift detection~~ (done: model expectations and drift
   checks).
6. ~~OpenLineage emission~~ (done).
7. **Airbyte/Singer adapter** for connector breadth. It runs third-party code, so it needs a
   sandboxed subprocess design (no network or file access beyond the source) before it ships.
8. Security: SQLCipher for `state.db` and mTLS remain deferred (section 3).
